## 实时速度

开启 GPS 后显示独立测速卡片，以设备测量时间更新读数。优先使用网页 `GeolocationCoordinates.speed` 或 Windows `GeoCoordinate.Speed` 提供的当前水平速度，单位从 m/s 换为 km/h；不使用停站区间距离除以时刻表时间，也不对设备速度取区间均值。设备报告的零速度保留为 0。

设备没有返回速度时，至少收集 3 个定位点、跨度至少 3 秒，最多使用最近 8 秒，在 WGS84 局部米制坐标中按位置精度加权拟合移动速度。此结果标注「GPS 短时估算」，显示采样跨度及由两端定位精度计算的误差参考，可能落后加减速过程几秒；这个误差参考不是校准后的速度置信区间。移动幅度不足以与 GPS 漂移区分时不报假零或假车速。

定位超过 10 秒未更新、误差超过 100 米、采样不连续、异常位置跳跃、轨迹漂移或设备速度极端突变时暂停实测读数并退回有明确标签的时刻预估。600 km/h 与速度变化检查仅用于剔除明显异常，不代表线路限速。设备没有提供速度精度。浏览器请求最多 1 秒的缓存，Windows 每秒读取系统定位；提供方实际更新频率由设备决定。

定位点只在当前开启的会话内存中保留最近 12 秒（最多 50 点），停止、隐藏页面／窗口或定位错误时清空，不写入本地存储或上传。未匹配所选车次时仍可查看设备移动速度，卡片明确说明它尚不能归属于所选列车。自定义历史观察时间不显示实时测速。

## 无 GPS 时的当前速度预估

GPS 未开启、权限被拒绝、定位过期或无法得到有效速度时，使用该日期的停站表、沿铁路折线累计的区间距离、车型速度等级推算观察时刻的速度。自定义观察时间同样支持预估。界面明确显示「预估速度」「线路＋时刻表预估」以及线性加速／匀速巡航／线性减速／停站阶段，设备有效读数始终优先，包含真实零速度。

每个实际停站区间从发车速度 0 开始，到下一站到达速度 0 结束，运行时间不含站内停站。按速度段使用恒定加速度，高速段降低加速度；进站使用恒定减速度。通过二分求解峰值速度，使加速、巡航和减速曲线的时间积分恰好等于沿线距离，并受车型速度上界约束。短区间允许无巡航的三角形曲线。地图标记与进度条采用同一曲线积分得到的已行距离，下一站仍由实际停站表决定。

车型上界区分 CR400／CRH380 的 350 km/h、CR300 及部分 CRH 动车组的 250 km/h、CR200J 的 160 km/h、CRH6A 的 200 km/h 与 CRH6F 的 160 km/h。具体型号未收录时标明参数参考：动车组暂取 350 km/h 上界，普速按车次等级使用 120／140／160 km/h 参考上界；这不是本次线路的实际限速。

牵引与制动参数是近似模型，不能当成本车测量结果。350 km/h 级车型的加速度取 0–200 km/h 为 0.4 m/s²、200–300 为 0.16、300–350 为 0.08，减速度取 0.45 m/s²；250 km/h 级取 0–160 为 0.4、160–250 为 0.22，减速度 0.45；CR200J 及普速参考取 0–100 为 0.22、100–160 为 0.14，减速度 0.35；CRH6 城际参考取 0–80 为 0.6、80–160 为 0.3、160–200 为 0.18，减速度 0.6。中车 CR400AF 产品参数给出的 0–200 平均加速度不低于 0.4 m/s²、350 km/h 剩余加速度不低于 0.05 m/s²仅作为量级依据，中高速分段值及其他车型斜率是建模假设，不是厂方公布的完整牵引曲线。

新鲜的正晚点资料同时修正运行时间和下一站时间，过期或时间顺序冲突则退回计划。停站、始发前、终到后按时刻表显示预估 0。没有有效铁路距离或距离与时刻不满足车型上界时说明原因，保留下一站判断；不以直线距离或任意固定车速填充。时刻表通常精确到分钟，未获得临时停车、进路和逐段实际限速，因此数值及位置仍可能偏离实际运行。

参数依据：[中车 CR400AF](https://www.crrcgc.cc/sfgf/2015-11/04/article_E7691BD1DADD4C799E29B682C86DADD3.html)、[CRH380A](https://www.crrcgc.cc/sfgf/2013-12/05/article_6DE3945F7E2B4887A2D46B0618286261.html)、[CR300AF](https://www.crrcgc.cc/crrcgc/2021-01/28/article_C9D1A07B70164E40AD1B619C28CCA15E.html)、[CR200J](https://www.crrcgc.cc/crrcgc/2026-05/08/article_2026050816295972455.html)、[CRH2A](https://www.crrcgc.cc/en/2016-02/24/article_3D1CC483DC82403D8C1F339C499D69D8.html)、[CRH6 城际平台](https://crrcgc.cc/crrcgc/2017-11/08/article_7C0F2266F07D443EA21B3099ED03D476.html)。

速度字段依据：[W3C Geolocation](https://www.w3.org/TR/geolocation/#speed-attribute)、[Microsoft GeoCoordinate.Speed](https://learn.microsoft.com/en-us/dotnet/api/system.device.location.geocoordinate.speed?view=netframework-4.8.1)。

## GPS 定位与完整地图

点击「开启 GPS 实时定位」后才请求定位权限。网页通过 `navigator.geolocation.watchPosition` 请求 `enableHighAccuracy: true`，持续接收设备 WGS84 位置；Windows 使用系统 `GeoCoordinateWatcher(High)`，无需 Google API key，不以 IP 城市定位替代 GPS。系统可能结合 GPS、Wi-Fi 和其他位置传感器，网页无法强制选择硬件 GPS，电脑也不一定具有 GPS 接收器。界面显示设备返回的精度和更新时间。

仅在**正在乘坐所选车次**时开启此功能。GPS 能定位设备，不能验证列车身份。设备位置在本地匹配本车次的铁路线路，依据沿线累计距离确定实际停靠站的前后关系；位置优先于时刻表的时间比例，因此晚点列车仍在广州南之前时，不会因为计划时间已过而把下一站改为深圳北。站场范围内结合时刻表与移动速度作保守判断，无法证明开出时不跳过即将到达的停靠站。

- RailGo 的 GCJ-02 线路和站点经过坐标逆转换为 WGS84，再绘制到 Web Mercator 地图，并与 GPS 匹配；不同坐标系不能直接混用。
- 定位超过 30 秒、报告误差超过 500 米、偏离线路、异常跳跃、线路重叠无法唯一匹配，或始发日期不属于当前行程时，停止 GPS 下一站判断，界面明确显示原因并退回时刻表估算。
- 蓝点表示未经吸附的设备位置，蓝色范围表示定位精度，绿点表示匹配的铁路位置或明确标注的时刻表估算，金点表示下一停靠站。GPS 模式显示至下一站的沿线距离，不用计划倒计时冒充 GPS 到站预测。
- 页面不保存或向本站上传定位历史。地图提供方仍会收到当前视野的瓦片请求。停止定位、切换页面、隐藏网页／Windows 窗口时停止定位读取；恢复可见时仅在本次定位开关仍开启的情况下恢复。
- 可拖动、缩放完整地图，切换「2D 地图／卫星图」，查看「全程／当前位置」，并放大地图区域。默认不拦截页面滚轮，使用地图的 +／− 控件或触摸手势缩放。

2D 底图为 [OpenStreetMap](https://www.openstreetmap.org/copyright)，遵循[瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)：保留署名、浏览器来源和缓存，不批量下载、不提供离线预取。Windows 请求使用可识别的应用 User-Agent。

卫星底图为 [EOX Sentinel-2 cloudless 2025](https://maps.eox.at/)，约 10 米分辨率，最大原生瓦片层级 14；放大后只放大已有像素。它是年度合成影像，**不是实时卫星直播，也不是列车遥测**。服务依据 [CC BY-NC-SA 4.0 非商业许可](https://cloudless.eox.at/documentation/license)使用，地图内保留完整署名和链接。此免费个人站按非商业用途集成；未来商业化需替换或获得商业许可。相关软件许可随 Windows 包内的 `public/rail-third-party-notices.txt` 一并分发。

## 使用

### 普速车与缺少完整线路的车次（1.8.0）

支持 Z、T、K 和四位数字车次。2026-09-29 实测 T21、K123、1461、Z22 的 `mapLine` 提供停站坐标，但 `train` 为空。现在独立保留与时刻表对应的站点，显示全程站点分布和下一停靠站，不再因没有轨道折线而丢弃地图资料。缺失或冲突的站点保留空位，避免错配下一站。

乘车时开启 GPS，首次有效定位会自动居中并跟随设备移动，仍可切换 2D／卫星图、返回全程站点视图和查看设备测速。缺少完整铁路线路时，下一站与运行区间按首站始发日期的时刻表推算，不宣称已完成 GPS 轨道匹配，也不以站间直线伪造铁路路线或精确列车坐标。没有 GPS 和可靠线路距离时，不能提供精确地图位置或可靠速度估算。

跨夜或跨两天的普速车应填写列车从首站出发的日期；该日期可能早于旅客的乘车日期。离车远程查询仅能查看时刻表估算，本站没有列车车载定位广播。

在 `cr.yukino.bond` 选择「列车位置与下一站」，填写车次和**首站始发日期**，点击「查询位置」。不需要余票查询或输入起终点。余票卡片中的「位置／下一站」可带入车次与日期。

默认跟随当前时间，显示运行区间、下一停靠站、预计到达时间、停站表和沿铁路线路的估算位置。取消「跟随当前时间」后，可用北京时间的完整日期／时间查看指定时刻；此时使用计划时刻，避免把现在的正晚点套到其他时刻。

2026-09-29 实测 G6003 的日期时刻表为：

| 停靠站 | 到达 | 发车 |
| --- | --- | --- |
| 长沙南 | 始发 | 10:00 |
| 广州南 | 12:02 | 12:06 |
| 深圳北 | 12:35 | 终到 |

因此观察时间 `2026-09-29 10:01`：运行区间为**长沙南 → 广州南**，下一停靠站为**广州南**。线路经过的节点或其他车站不会进入下一站判断。12:02–12:06 为广州南停站期间，下一停靠站为深圳北；12:35 起无下一站。此例在测试中作回归数据，产品查询没有硬编码 G6003，也不以此表替代其他日期的资料。

## 数据与算法

官方车次、停站表与正晚点经本站 `/api/rail` 查询 12306。RailGo 仅由客户端直接读取官方缺少的车型、配属及铁路坐标，不建立其公开中转接口；页面保留显著署名。

- [12306 停站查询](https://kyfw.12306.cn/otn/czxx/init)：先通过 `search.12306.cn/search/v1/train/search` 精确核对车次、始发日期和唯一 `train_no`，再访问 `kyfw.12306.cn/otn/queryTrainInfo/query`，传入 `leftTicketDTO.train_no` 与 `leftTicketDTO.train_date`。按 `station_no` 排序，校验完整站序、始发终到、到发时间及 `arrive_day_diff`；站名和电报码取官方车站列表。
- [铁路线路点](https://api.railgo.dev/479769351e0)：`mapLine`，按线路分段的 `index` 排序、检查方向与连接，使用 GCJ-02 坐标。将该日期每个停靠站投影到线路并校验顺序和距离，资料不匹配时不画虚构直线。
- [12306 正晚点](https://hzfw.12306.cn/zgzfw/resources/web/zwdcx.html)：使用该官方页面公开的 `hzfw.12306.cn/zgzfw/trainTime/query`，按实际停靠站车次、站名和到达／出发类型查询。它只提供未来三小时信息；每次最多查询两个邻近停站，不遍历全程站点。没有报告、要求验证或服务异常时标明暂无官方资料，不改查 RailGo。报告时钟结合停站的实际运行日期解释，区别到站与发车报告、正点／晚点／早点及预计状态。
- [车型补充](https://api.railgo.dev/366464494e0)：仅查询具体车次的 `/api/train/query?train=车次`，读取 `car` 与 `carOwner`，并以 `numberFull` 和 `rundays` 核对身份及日期。不使用返回的时刻表、交路、票额等内容；官方已有车型时跳过补充。停站表先显示，车型随后异步补充。

所有时间以 UTC+8 解析，与设备设置的时区无关。时刻表的 `day` 以到站日期计，停站跨过午夜时发车顺延一天。首站发车前为等待发车，途中停站显示当前站及其后下一停靠站，终点到达后不再显示下一站。

GPS 未开启或无有效匹配时，优先使用上述加速、巡航、减速曲线的积分，在两站之间的铁路折线上按累计距离插值。速度曲线无法可靠求解时仅保留时刻表时间比例的位置参考并显示速度缺失原因。**这个回退模式是时刻估算**；临时停车、线路临时调整等会产生偏差。线路接口不接受日期，核对停站不能证明任意历史日期的完整径路。

位置每秒在本地重算，官方正晚点每分钟刷新，官方时刻表缓存 15 分钟；车型和铁路坐标缓存 12 小时，同车次车型请求跨区间共用、最多三个并发，失败后至少 15 分钟再试。相同请求合并，保留实际获取时间。正晚点超过 3 分钟自动停用，时刻表超过 20 分钟无法刷新则暂停位置推算。地图／正晚点缺失不会阻止显示官方时刻表对应的运行区间与下一站。
