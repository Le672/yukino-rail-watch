# 列车位置与下一停靠站

2026-09-29：网页与 Windows 1.4.0 同步加入此功能。

2026-09-29：网页与 Windows 1.5.0 改用完整交互地图，新增 GPS／设备实时定位。

## GPS 定位与完整地图

点击「开启 GPS 实时定位」后才请求定位权限。网页通过 `navigator.geolocation.watchPosition` 请求 `enableHighAccuracy: true`，持续接收设备 WGS84 位置；Windows 使用系统 `GeoCoordinateWatcher(High)`，无需 Google API key，不以 IP 城市定位替代 GPS。系统可能结合 GPS、Wi-Fi 和其他位置传感器，网页无法强制选择硬件 GPS，电脑也不一定具有 GPS 接收器。界面显示设备返回的精度和更新时间。

仅在**正在乘坐所选车次**时开启此功能。GPS 能定位设备，不能验证列车身份。设备位置在本地匹配本车次的铁路线路，依据沿线累计距离确定实际停靠站的前后关系；位置优先于时刻表的时间比例，因此晚点列车仍在广州南之前时，不会因为计划时间已过而把下一站改为深圳北。站场范围内结合时刻表与移动速度作保守判断，无法证明开出时不跳过即将到达的停靠站。

- RailGo 的 GCJ-02 线路和站点经过坐标逆转换为 WGS84，再绘制到 Web Mercator 地图，并与 GPS 匹配；不同坐标系不能直接混用。
- 定位超过 30 秒、报告误差超过 500 米、偏离线路、异常跳跃、线路重叠无法唯一匹配，或始发日期不属于当前行程时，停止 GPS 下一站判断，界面明确显示原因并退回时刻表估算。
- 蓝点表示未经吸附的设备位置，蓝色范围表示定位精度，绿点表示匹配的铁路位置或明确标注的时刻表估算，金点表示下一停靠站。GPS 模式显示至下一站的沿线距离，不用计划倒计时冒充 GPS 到站预测。
- 页面不保存或向本站上传定位历史。地图提供方仍会收到当前视野的瓦片请求。停止定位、切换页面、隐藏网页／Windows 窗口时停止定位读取；恢复可见时仅在本次定位开关仍开启的情况下恢复。
- 可拖动、缩放完整地图，切换「2D 地图／卫星图」，查看「全程／当前位置」，并放大地图区域。默认不拦截页面滚轮，使用地图的 +／− 控件或触摸手势缩放。

2D 底图为 [OpenStreetMap](https://www.openstreetmap.org/copyright)，遵循[瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)：保留署名、浏览器来源和缓存，不批量下载、不提供离线预取。Windows 请求使用可识别的应用 User-Agent。

卫星底图为 [EOX Sentinel-2 cloudless 2025](https://maps.eox.at/)，约 10 米分辨率，最大原生瓦片层级 14；放大后只放大已有像素。它是年度合成影像，**不是实时卫星直播，也不是列车遥测**。服务依据 [CC BY-NC-SA 4.0 非商业许可](https://cloudless.eox.at/documentation/license)使用，地图内保留完整署名和链接。此免费个人站按非商业用途集成；未来商业化需替换或获得商业许可。相关软件许可随 Windows 包内的 `public/rail-third-party-notices.txt` 一并分发。

## 使用

在 `cr.yukino.bond` 选择「列车位置与下一站」，填写车次和**首站始发日期**，点击「查询位置」。不需要余票查询或输入起终点。余票卡片中的「位置／下一站」可带入车次与日期。

默认跟随当前时间，显示运行区间、下一停靠站、预计到达时间、停站表和沿铁路线路的估算位置。取消「跟随当前时间」后，可用北京时间的完整日期／时间查看指定时刻；此时使用计划时刻，避免把现在的正晚点套到其他时刻。

2026-09-29 实测 G6003 的日期时刻表为：

| 停靠站 | 到达 | 发车 |
| --- | --- | --- |
| 长沙南 | 始发 | 10:00 |
| 广州南 | 12:02 | 12:06 |
| 深圳北 | 12:35 | 终到 |

因此观察时间 `2026-09-29 10:01`：运行区间为**长沙南 → 广州南**，下一停靠站为**广州南**。线路经过的节点或其他车站不会进入下一站判断。12:02–12:06 为广州南停站期间，下一停靠站为深圳北；12:35 起无下一站。此例在测试中作回归数据，产品查询没有硬编码 G6003，也不以此表替代其他日期的资料。

## 数据与算法

数据直接由客户端访问 [RailGo 数据服务](https://api.railgo.dev/)，不建立公开中转接口。公开页面底部保留显著来源链接。

- [车次主数据](https://api.railgo.dev/479755220e0)：`https://rg-api.zenglingkun.cn/api/v2/getTrainMain`，传入完整 `trainNum` 及 `date`。必须确认复车次列表中有该车次、开行日列表中有该日期、时刻表站序完整且时间递增。
- [铁路线路点](https://api.railgo.dev/479769351e0)：`mapLine`，按线路分段的 `index` 排序、检查方向与连接，使用 GCJ-02 坐标。将该日期每个停靠站投影到线路并校验顺序和距离，资料不匹配时不画虚构直线。
- [车次正晚点](https://api.railgo.dev/406912287e0)：`getTrainDelayAll`，按站名及电报码匹配，区别正点、晚点／预计晚点、早点／预计早点、未维护。延误数值本身是非负的，正负由代码决定。早点不用于推断提前发车。若修正后时刻顺序冲突，退回计划时刻并提示。

所有时间以 UTC+8 解析，与设备设置的时区无关。时刻表的 `day` 以到站日期计，停站跨过午夜时发车顺延一天。首站发车前为等待发车，途中停站显示当前站及其后下一停靠站，终点到达后不再显示下一站。

GPS 未开启或无有效匹配时，按上一停靠站发车到下一停靠站到达的时间比例，在两站之间的铁路折线上按累计距离插值。**这个回退模式是时刻估算**；途中加减速、临时停车、线路临时调整等会产生偏差。线路接口不接受日期，核对停站不能证明任意历史日期的完整径路。

位置每秒在本地重算，正晚点每分钟刷新，时刻表缓存 15 分钟，线路点缓存 1 小时；相同请求合并。缓存保留实际获取时间。正晚点超过 3 分钟自动停用，时刻表超过 20 分钟无法刷新则暂停位置推算。地图／正晚点缺失不会阻止显示可验证时刻表对应的运行区间与下一站。
