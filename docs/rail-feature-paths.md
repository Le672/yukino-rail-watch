# 功能地址与停站表

铁路子域名首页保持 `https://cr.yukino.bond/`，默认显示余票查询。功能切换同步地址，直接打开或刷新对应地址会进入相应功能，浏览器前进／后退也会同步选择：

| 功能 | 路径 |
| --- | --- |
| 余票查询与监控 | `/ticket` |
| 中转行程 | `/transfer` |
| 列车位置与下一站 | `/live` |
| 车站大屏 | `/arrivalinfo` |

旧 `/cr?view=board` 等链接保留兼容，进入后替换为规范路径，保留车站等查询参数。主站的 `/cr` 入口继续提供铁路功能。页面切换保留余票控制器，避免重启监控或重复加载车站列表。Windows 使用独立侧栏导航。

位置查询的停站表保持浅色卡片与原有下一站高亮，展示停靠站、当地车次代码、始发站、终到站、计划到达／发车、停靠时长、站台、检票口、列车状态、检票状态及行程进度。窄屏可横向滑动表格，页面不横向溢出。

停站详情使用 `/api/rail?mode=journey-board&train=…&date=…&stops=…`，每批最多 6 站。服务端从经过日期、始发终到及站序验证的 12306 时刻表取得车站与列车身份，再复用大屏的官方开行、站台与状态查询；不下载各站完整大屏，不接受客户端提供的站名替代官方停站。

跨日始发日期保留不变，查询站台／检票口时按各站实际到发日期提交；中途变更车次代码时使用该站的实际代码。始发与终到分别标注，停靠时长按实际跨日时间差计算。

首次补齐各站计划站台／检票口，之后每分钟只刷新临近停站的实时资料；复用五分钟计划缓存及相同请求。表格缺少列车状态时复用位置查询已取得的官方正晚点报告，按停站名及电报码唯一匹配，覆盖超过计划时刻的晚点停站，无需额外请求。界面隐藏超过两分钟的实时状态，保留已取得的计划站台／检票口。自定义观察时间仅展示计划信息。官方检票及取消状态未提供时不按时钟推测。RailGo 仅补充缺失车型及铁路坐标，页底保留小型来源署名与文档链接。
