# 中转与余票查询日期

余票查询采用北京时间的当天至后 14 天，即 12306 的 15 天预售期（含当天）：[官方规则](https://kyfw.12306.cn/otn/gonggao/saleTicketMeans.html?linktypeid=means1)。各车站的起售时间仍以 12306 为准。

中转页重新打开时，已过期的保存日期会更新为今天，并提示核对；出发站、到达站、中转站和换乘条件保持原值。有效的未来日期继续保留。日期选择范围会在跨日后刷新。

前端在启动中转规划前校验日期；服务端在读取车站表、建立会话和请求 12306 前再次校验。过期或超出预售期的余票、票价、中转节点请求返回 HTTP 400 和具体原因，不能将历史余票当成当前余票。

有效日期也可能遇到短暂网关故障。中转查询同一区间最多自动重试两次，间隔逐步增加，遵守服务端的 Retry-After，支持 60–120 秒网关恢复间隔并显示重试进度；并发区间数限制为两条，取消操作中止正在等待的重试。HTTP 400／404 不重试；持续失败保留具体提示，不能转为空车次。[Cloudflare 的官方重试间隔](https://developers.cloudflare.com/fundamentals/reference/error-responses/#5xx-retry-after-values)中，502 为 60 秒，504／521／522／523／524 为 120 秒。

中转区间、票价和推荐节点使用只读 POST 查询，响应明确为 `Cache-Control: no-store`。参数、12306 上游查询、日期验证与 GET 保持一致；现有 GET 接口仍可使用。POST 无请求体且只带常规 Accept 头，Windows 本地界面沿用公开数据的 CORS 响应。

跨日行程的后续乘车日如果尚未进入预售期，会跳过该日余票请求并标注未开售；这不代表没有列车或没有中转方案。历史始发日的停站表、列车位置和大屏使用各自的日期规则。

2026-10-09 修复核验：旧版使用保存的 2026-10-07 查询肇庆东至广州南时返回 Cloudflare 502；同一区间的 2026-10-09 查询正常返回官方车次、余票和票价。修复针对无效日期请求，实际网络或 12306 服务异常仍会明确提示。
