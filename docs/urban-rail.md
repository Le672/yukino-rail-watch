# 全国城市轨道可选接驳

## 使用

进入「中转行程」，勾选「城市轨道交通（可选，默认关闭）」。起终点可选官方铁路站或带运营网络的轨道站名，例如「北京地铁 · 天安门东（轨道）」。重复站名必须从候选中选择完整名称；指定中转站仍使用 12306 官方铁路站。

默认先展示铁路方案，城市轨道为备选；每组分别按所选票价、耗时、时间、余票或车型排序。「方案优先顺序 → 按所选排序统一比较」可手动取消分组优先级。用户开启的选项会在本机保存。

支持地铁、轻轨、有轨电车、单轨、磁浮、非 12306 市域轨道、APM 及轨道缆车。没有城市白名单；从全国轨道线路关系生成有向网络，处理上下行、支线、环线与同名邻近站换线。公交、出租车、轮渡和空中索道不作为轨道交通。

## 数据与实际范围

2026-10-03 快照收录 **998 条方向／支线、7390 个去重轨道站**，包括内地及港澳台开放数据。方向／支线数不是独立线路数。数据来自 OpenStreetMap，区域边界由 Geofabrik 提供，不代表每座城市的运营方确认；开放数据可能漏线、漏站或未及时更新，页面公开快照日期和数量，不声称已穷尽全部运营线路。

国家铁路及可由 12306 查询的城际／市域班次，继续通过官方接口取得车次、票价、时刻及余票。轨道网络只补充开放的线路、站序和地理坐标。已识别的 12306 城际服务不会转换成猜测的地铁班次。

网络按需载入并在本机计算，网页、Windows、Android 和 iOS 使用同一快照。不会把用户行程或 GPS 发给 Overpass，也不会在每次查询时爬取城市线路。

## 时间、票价及筛选

- 城市轨道没有所选日期的实时班次保证，标为「预估行程／运营待确认」。如果来源给出整线时长，按站间距离分配；缺失时按交通类型的规划速度、停站时间估算。此值不是实时测速。
- 候车以来源间隔的一半估计，缺失时预留 6 分钟；出入站及按地理距离估计的步行时间分别加入。换线另外预留 5 分钟，并再次计候车。邻近站按名称和距离连接，实际步行通道、道路及安检须现场确认。
- 进入铁路另加用户设置的同站最短预留，且必须留足换乘时间；估算本身不保证可赶上列车。来源的首末班仅展示，不把未知运营日期、停运或节假日班次视为已核实。
- 城市轨道票价目前无可核实区间价格，保持未知。含城市轨道方案的完整总价未知时单列铁路小计，不使用零元。车型同样不猜测；轨道不伪造车次或可预订余票。
- 车型和有票筛选只检查铁路段，页面明确区别；纯轨道方案没有铁路余票，不能通过「仅看铁路段有票」。
- 每段轨道显示线路、上下车站、站数、途经站、交通类型、估算乘车时间及来源提供的运营信息。铁路各程保持真实车型、票价、余票、时间与位置入口。

自动规划仍有查询预算：2026-10-12 起先沿实际有向网络查找全部已映射、可达的铁路站，再应用候选上限，不先按直线距离截取 24 站。起终点分别额外纳入最多 8／16／32／32 个接驳铁路站，对应 64／128／256／512 的搜索范围；到达端使用反向搜索取得正确的进站方向。两程铁路之间，每个到站额外考虑最多 16／32／64／64 个轨道可达铁路站，可越过同城标识和本次铁路候选名单。两次铁路中转都可插入城市轨道。

接驳发现不超过 180 分钟和 4 次换线；铁路之间的接驳同时受最长等待及铁路进站预留约束。线路搜索一次遍历多个目标，缓存邻近站换线关系与已发现路径，避免逐个站重复检索全国图。官方铁路查询仍最多两个并行请求、总量受查询范围限制；分批查询首程和接续，及时显示已确认结果。地面与轨道衔接若对应相同铁路区间，则共享请求和连接预算，不丢弃各自可行的衔接方式。截断、失败和实际纳入的候选数都会显示；未选中或未完成不表示其他路线不存在。

结果页显示当前车型／余票筛选下含轨道方案的最短耗时，与铁路方案比较，并可一键切换到按耗时排序的轨道备选。默认关闭与铁路优先设置保持不变。城市轨道起终点间已有可达轨道路线时直接本机查询，不请求无关铁路班次。

## 更新与许可

接驳候选同时参考全国铁路枢纽、行程方向和轨道耗时。此排序只用于安排官方查询，避免近处的小站占满接驳名额；不依据拓扑推造车次。例如广州南至惠州北的标准搜索也会纳入广州新塘，不必手动指定广州南—新塘的地铁衔接。

`src/data/urban-rail-network.json` 是可检视的完整发布快照；仅该派生地图数据库采用 [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/)，© OpenStreetMap contributors。源码许可与数据库许可分别适用。页面结果底部保留 [OpenStreetMap 署名](https://www.openstreetmap.org/copyright)。

维护者运行 `node scripts/update-urban-rail.mjs` 读取一次全国快照并重新构图，或提供先前保存的 Overpass JSON 作为参数。公共服务失败、超时、数据意外为空或过小时保留旧文件，不发布空网络。默认读取轨道关系、成员站点、实际轨道类型、城市标签与铁路坐标；邻国线路按区域边界排除。可通过 `URBAN_OVERPASS_URL` 指定自有或授权数据服务。

也可从 [Geofabrik 区域数据](https://download.geofabrik.de/asia/china.html) 下载完整 PBF，安装官方 `osmium` Python 库后运行 `python scripts/extract-urban-pbf.py output.json china.osm.pbf [taiwan.osm.pbf]`，再用 `node scripts/update-urban-rail.mjs output.json` 转换。更新后检查交通类型、真实路线与测试，通过发布流程同步各端。
