# 车站到发大屏

网页 `https://cr.yukino.bond/cr?view=board` 与 Windows 1.10.0 的“车站大屏”共用官方数据网关。桌面端保留独立桌面导航和布局。移动客户端暂停开发，本次不构建或发行移动版。

## 使用

选择 12306 车站和车站到发日期，可查询前 13 天至后 14 天内的计划信息。支持到达／出发切换、车次及始发终到站筛选。当天默认展示从当前时刻前 5 分钟起的车次，关闭“近期车次”查看完整列表。每屏 6 趟，可手动翻页或每 15 秒自动翻页；全屏显示大屏，窄屏表格横向滚动。

每分钟刷新时刻表与当前屏车次状态；标签页进入后台后暂停，恢复前台时补查。Windows 大屏需要保持窗口运行。余票后台通知逻辑独立运行。

## 数据与边界

| 内容 | 官方入口 | 处理 |
| --- | --- | --- |
| 车站列表 | `kyfw.12306.cn/otn/resources/js/framework/station_name.js` | 精确匹配车站电报码 |
| 当站计划到发 | `mobile.12306.cn/wxxcx/wechat/bigScreen/queryTrainByStation` | POST，日期 YYYYMMDD；核验车站、当站日期和始发日；始发无到达、终到无出发；跨日停靠单独处理 |
| 逐日开行核验 | `mobile.12306.cn/wxxcx/wechat/bigScreen/queryTrainDiagram` | 仅当前屏逐日核对始发日，明确 flag=0 时显示“当日不开行”；不等同于临时取消，避免把基础运行图都当作当天实际开行 |
| 站台、检票口 | `mobile.12306.cn/wxxcx/wechat/bigScreen/getExit` | 显式 `platform`、`wicket`；列表字段 `platform_no` 常是检票口，禁止把它直接当站台 |
| 官方实时大屏 | `mobile.12306.cn/wxxcx/openplatform-inner/miniprogram/wifiapps/appFrontEnd/v2/lounge/open-smooth-common/kpBigScreen/getBigScreenByStationCodeAndTrainDate` | 当天按到发方向查询；当前接口可能不可用，失败缓存 5 分钟；只接受更新不超过 2 分钟且身份匹配的记录 |
| 正晚点补充 | `hzfw.12306.cn/zgzfw/trainTime/query` | 当前屏、未来 3 小时内的到达／出发分别查询；只有匹配车次、站名和有效预计时刻时显示正点／早点／晚点及分钟数 |

2026-10-05 实测：当站时刻表及站台／检票口接口可用；实时大屏接口返回“接口调用失败”。因此检票状态可能显示“未提供”；没有实际报告也不会标为正点。旧的 `/otn/czxx/query` 返回 404，旧 Wi-Fi 大屏接口返回不可用，未将它们作为可用来源。

候车、检票中、停检分别对应官方明确状态 1、2、3，正点／晚点／预计晚点对应 4、5、6，已到站为 7，停运／取消为 8。不把停售、无余票、列表缺失或当日无计划等同于取消。不按固定“开车前 X 分钟”推算检票。停靠时长由计划到发时刻计算，不是列车实际停靠耗时。

未提供的值显示“未提供”或“—”。数据更新失败保留查询快照；超过两分钟隐藏过期实时状态并标为旧快照。车站现场屏幕与工作人员通知优先。

网关按车站／日期合并查询，计划缓存 60 秒，行详情缓存 55 秒，停台缓存 5 分钟；每个前端最多同时补查两行，避免逐分钟遍历全站上千车次。仅访问 12306 域名，不调用 RailGo 或其他第三方大屏接口。
